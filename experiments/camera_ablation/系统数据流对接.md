# 系统数据流对接（机械臂控制 + 视频流）

记录采集系统当前的对接方案：基于 WebRTC / 服务器转发，一条链路承载**机械臂摄像头视频流**和**双向控制/反馈数据**。供采集"条件A/B"演示数据用，最终落盘成转换器吃的 `states.csv` / `actions.csv` / `video.mp4`。

当前实验变量不是"有没有摄像头"，而是**摄像头视频流显示在手机端还是电脑端**：

- 条件A：机械臂摄像头视频流经服务器发送到手机客户端，操作者在手机上观察末端执行器位置，并用手机控制末端。
- 条件B：机械臂摄像头视频流经服务器发送到电脑端，操作者在电脑屏幕上观察末端执行器位置，并用手机控制末端。

## 1. 系统拓扑

```
   ┌─────────────────────────┐                      ┌──────────────────────────────┐
   │  机械臂端 (推流+控制板)   │                      │  操作者端 (手机APP / 电脑)     │
   │                         │   WebRTC / 服务器转发  │  Target1.1.webrtc receiver    │
   │  ┌─ 摄像头 ──视频轨道───┼──────────────────────┼─► RTCVideoRenderer 显示画面   │
   │  │                     │   (A手机显示 / B电脑显示)│     (A/B 都看这路画面)        │
   │  ├─ 控制板 ─DataChannel─┼◄─────"control"───────►┼─ robot_control_channel.dart   │
   │  │   收 delta→IK→电机   │   ① {"d":[...]} 下行   │      imu_teleop.dart (产生delta)│
   │  │   读关节角→回传      │   ② {"j":[...]} 上行   │                              │
   └──┴─────────────────────┘                      └──────────────────────────────┘
```

- **一条 WebRTC PeerConnection/服务器转发链路** 同时跑：1 路视频轨道 + 1 个 DataChannel(`control`)。
- 视频方向：机械臂端 → 操作者端（单向，看画面）。
- 控制/反馈方向：DataChannel 双向（下行 delta 指令，上行关节角）。

## 2. 三条数据流

### 2.1 视频流（机械臂摄像头 → 操作者）
- 机械臂端把摄像头作为 WebRTC 视频轨道推出；操作者端 `RTCVideoRenderer` 显示。
- 现状：[player_screen.dart](../../../../../Target1.1.webrtc/webrtc_receiver/lib/player_screen.dart) 已实现接收+渲染（`flutter_webrtc`，`RTCPeerConnection _pc`）。
- 实验用途：**条件A** 在手机客户端显示这路画面；**条件B** 在电脑端显示这路画面。
- A/B 都需要把同一路机械臂摄像头视频保存为 `video.mp4` 进数据集，训练时都作为 `observation.images`。

### 2.2 控制流（手机 → 机械臂，下行）
- 来源：手机 IMU。[imu_teleop.dart](../../../../../Target1.1.webrtc/webrtc_receiver/lib/imu_teleop.dart)
  - 陀螺仪角速度 × dt → 姿态增量 `(dyaw,dpitch,droll)`
  - 加速度计倾角当摇杆 → 位置增量 `(dx,dy)`，`dz` 预留
  - 离合开关：按住才输出，防手抖
- 发送：[robot_control_channel.dart](../../../../../Target1.1.webrtc/webrtc_receiver/lib/robot_control_channel.dart) 的 `sendDelta()`
  - 经 DataChannel `control` 发 `{"t":<ms>,"d":[dx,dy,dz,dyaw,dpitch,droll]}`

### 2.3 反馈流（机械臂 → 手机，上行）
- 机械臂端读各关节当前角度，经 DataChannel 回传 `{"j":[j1,...,jN]}`。
- 手机端 `robot_control_channel.dart` 的 `_onMessage` 接收，更新 `_lastJoints`。
- 用途：生成 `states.csv` 的关节角；末端位姿由转换器用 DH 表做 FK 补出。

## 3. DataChannel 协议（`control` 通道，JSON 文本）

| 方向 | 消息 | 字段 | 单位 |
|------|------|------|------|
| 手机→机械臂（控制） | `{"t":<ms>, "d":[dx,dy,dz,dyaw,dpitch,droll]}` | `t` 时间戳ms；`d` 6维末端 delta | 位置 m，角度 rad(ZYX) |
| 机械臂→手机（反馈） | `{"j":[j1,j2,...,jN]}` | `j` N 个关节角 | rad |

- DataChannel 配置：`ordered=true, maxRetransmits=0`（低延迟，宁丢不卡，适合遥操作）。
- delta 是**增量**：机械臂端把它叠加到当前末端位姿上执行（需 IK）。

## 4. 采集录制与落盘

录制由 `robot_control_channel.dart` **事件驱动**：每路按自己的到达时刻记一行（带时间戳），
不在采集端硬对齐；对齐留给离线的 `time_sync.py`（见第 5 节）。三路共用手机时钟（秒）。

```
raw_ts/cond_X/episode_000/
    phone.csv        # timestamp, dx,dy,dz,dyaw,dpitch,droll   每次 sendDelta 写一行
    robot.csv        # timestamp, j1,...,jN                     每次关节角回传写一行
    video.mp4        # A/B 都有：机械臂摄像头视频流录像
    video_meta.json  # {"start_ts": <秒>, "display": "mobile|pc"} 供视频对齐和条件记录
```

- `startEpisode(dir)` 开始一条演示，`stopEpisode()` 结束并 flush + 写 `video_meta.json`。
- 视频录制（`video.mp4`）目前**未在模块内实现**，需另接（见第 6 节未决项）。

## 5. 与训练流水线的衔接

```
raw/cond_X/episode_* ──► convert_raw_to_lerobot.py（--dh_config 做 FK）──► LeRobot 数据集
                                                                            └─► lerobot-train (ACT)
```
- state = `[关节角] + [FK 末端位姿]`，action = `[6维 delta]`。详见 [README.md](README.md)。
