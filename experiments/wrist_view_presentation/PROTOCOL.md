# Wrist View Presentation 研究协议

状态：正式协议。任何实质修改都必须在采集前版本化、说明原因并重新预注册，不能根据已观察
结果修改。

## 研究问题

在同一机器人平台、同一腕部摄像头视角、同一手机 IMU 控制、相同任务和相同模型训练配置
下，腕部视觉反馈与运动控制共置或空间分离，是否会影响人类遥操作演示质量、数据集可学习性
和模仿学习策略的真实机器人性能？

协议保持中性，不预设 `A_mobile_colocated` 或 `B_desktop_separated` 更优。

## 正式条件与唯一主要自变量

```json
{
  "study": {
    "name": "wrist_view_presentation",
    "paired_within_participant": true,
    "counterbalance_condition_order": true,
    "conditions": {
      "A_mobile_colocated": {
        "camera_present": true,
        "camera_view": "wrist",
        "display": "mobile",
        "control": "phone_imu",
        "feedback_control_relation": "colocated"
      },
      "B_desktop_separated": {
        "camera_present": true,
        "camera_view": "wrist",
        "display": "desktop",
        "control": "phone_imu",
        "feedback_control_relation": "spatially_separated"
      }
    }
  }
}
```

唯一主要自变量是腕部视觉反馈的呈现配置：控制与反馈共置，或控制与反馈空间分离。显示设备
及 `feedback_control_relation` 是该配置的操作化字段；摄像头存在性、视角和控制方式不是
自变量。

固定变量至少包括机器人与末端工具、腕部摄像头与安装位姿、视频源、分辨率和目标帧率、手机
与 IMU 映射、任务物体和初始状态、工作空间、成功阈值、超时、每档任务试次数、采集 schema、
同步/转换方法、模型结构、优化器、训练步数、batch、随机种子集合和评估任务集。

## 理论机制与假设

假设（待验证）：视觉反馈与运动控制的空间关系可能改变注意切换、感知—动作映射负担、修正
动作和停顿，从而影响演示轨迹及其训练出的策略。该机制没有预设方向，不能写成已成立事实；
延迟、掉帧或学习/疲劳效应也可能解释观测差异。

## 参与者内配对与顺序平衡

- 每位参与者完成两个正式条件；每个 `pair_id` 对应同一参与者、任务、难度和试次的一对记录。
- 一个 `pair_id` 恰好含一条 `A_mobile_colocated` 和一条 `B_desktop_separated`。
- 同一参与者在全部任务中保持一种条件顺序；参与者之间将 A-first 与 B-first 数量平衡到最多
  相差 1。
- 实际 `condition_order`、参与者经验和中止情况必须记录，不得事后改写。

## 任务难度与结果定义

在采集前冻结至少一项简单、一项中等和一项困难任务。每项任务必须给出物体、初始位姿、目标
区域、允许接触、完成动作和计时起止点。

- 成功：在超时前完成规定抓取与放置，放置误差不超过预注册阈值，且没有碰撞、抓取失败或
  用户中止。
- 失败：碰撞、抓取失败、超时、放置误差超阈值、用户中止或预注册的其他类型。采用二分规则，
  非成功即失败。
- 超时：`completion_time_s` 达到预注册 `timeout_s` 而任务未成功。
- 放置误差：按冻结的参考坐标系和测量程序计算目标与最终物体/末端位置的距离。

阈值必须来自任务容差、安全要求或先验设计，不能依据组间结果调节。

## 协变量与数据质量

每条 episode 记录端到端视频延迟、掉帧、时钟映射不确定度和实际帧时间。它们作为预注册
协变量、敏感性分析量或质量控制量，不改变主要自变量。不得仅因结果不利而删除高延迟或掉帧
episode；排除阈值和处理方式必须在看结果前冻结。

## 等量数据与数据集构建

- 每位参与者、每个任务、难度和试次在两个条件中成对采集；分析只使用完整配对或按预注册
  缺失规则处理。
- 两个条件使用相同目标 episode 数、采集时长规则、摄像头视频 schema 和状态/动作特征。
- 两组都保存同源腕部视频、视频元数据和真实逐帧时间戳。
- 同一同步、裁剪、FK、转换和质量门禁应用于两组；所有排除保留原因和原始清单。

## 参与者安全划分

在训练前按 `participant_id` 冻结 train/validation/test。一个参与者的所有任务、条件和重复
试次只能属于一个 split；每个 `pair_id` 也只能属于一个 split。划分按参与者完整难度档案
分层并保存 `split_seed`。任何参与者泄漏都会使正式训练或评估失败。

## 多随机种子训练与统一测试集

- 两个条件使用相同且至少三个预注册整数种子。
- 除 `dataset_repo_id` 外，A/B 训练配置逐字段相同；输出路径和任务名只作标识，不是超参数。
- 模型选择只使用 validation；冻结后在同一参与者隔离的 test 任务集上比较。
- 报告每个种子和跨种子方差，不挑选最有利种子。
- 统一测试集输出物理单位下的逐维 action MAE/MSE/RMSE、平移/旋转误差及复现元数据。

## 真实机器人 rollout

用每个条件的冻结策略在同一机器人、同一安全限制、相同任务/物体位置分布和相同试次数上
rollout。条件与种子顺序应随机或平衡；评估者在可行时对训练数据来源盲法。记录每个试次的
成功、完成时间、碰撞、抓取失败、放置误差、中止和场景是否未见。

真实机器人 rollout 是判断哪一数据集训练出的策略实际表现更好的主要证据。训练 loss 和离线
MSE 只能作为辅助证据，不能替代 rollout。

## 指标与证据层级

### 1. 人类演示质量

- 成功率、完成时间、放置误差；
- 碰撞、抓取失败和失败类型；
- 轨迹长度、速度、加速度和 jerk；
- 修正动作、方向反转和停顿次数。

### 2. 数据集可学习性

- validation loss；
- 统一测试集 action MAE/MSE/RMSE 和平移/旋转误差；
- 多随机种子方差；
- 预注册数据量子集上的学习曲线。

### 3. 策略实际性能

- 真实机器人 rollout 成功率（主要指标）；
- 完成时间、碰撞率和放置误差；
- 未见场景或物体位置下的泛化表现。

人类演示与连续特征以参与者为推断单位，配对报告效应量和置信区间，并对多特征检验使用 FDR。
成功率采用适合配对二元结果的检验。条件×难度和顺序效应作为预注册次要分析。

## 禁止的旧实验解释（迁移约束）

以下表述仅在本节作为禁止项出现，不得用于正式代码、配置、结果或结论：

- 把研究解释成“无摄像头 vs 有摄像头”或 camera presence/ablation；
- 通过删除视频列构造某个正式条件；
- 把不同摄像头安装位置或不同视角当作条件；
- 用公开占位数据、合成数据、训练 loss 或离线 MSE 推断哪个条件更优；
- 把“视觉—运动协调改善”写成已证实结论。

若历史数据确需兼容，必须使用单独、显式标记的迁移工具并留下来源审计；当前仓库没有需要
保留的历史别名兼容路径。
