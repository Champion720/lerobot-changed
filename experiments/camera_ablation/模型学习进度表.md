# LeRobot / ACT 模仿学习模型学习进度表

这份进度表用于一步步理解当前实验里的模型到底在做什么。

当前研究问题：

> 同一机械臂摄像头视频流分别显示在手机端和电脑端时，用户通过手机操控末端执行器采集到的数据，哪一组更适合用于模仿学习。

模型要学习的核心关系：

```text
输入：observation.state + observation.images
输出：action

也就是：
机械臂当前状态 + 摄像头画面 -> 人类操控时产生的末端动作
```

## 阶段 2：理解系统数据流

### 三条数据流

```text
机械臂摄像头 -> 视频流 -> 手机端或电脑端显示
手机 IMU/控制输入 -> action delta -> 机械臂
机械臂关节角 -> robot feedback -> 手机/记录端
```

### 需要理解

- 视频流负责让操作者看到末端执行器位置。
- 控制流负责把手机产生的末端 delta 发给机械臂。
- 反馈流负责记录机械臂当前关节角。

### 自测问题

- `video.mp4` 从哪里来？
- `phone.csv` 记录的是什么？
- `robot.csv` 记录的是什么？

## 阶段 4：理解时间同步

重点文件：

```text
experiments/camera_ablation/time_sync.py
```

它做的事：

```text
robot.csv + phone.csv + video.mp4
        ↓
对齐到统一 30Hz 时间网格
        ↓
states.csv + actions.csv + video.mp4
```

同步方法：

| 数据 | 同步方式 | 原因 |
|---|---|---|
| 机器人关节角 | 线性插值 | 关节状态是连续变化的 |
| 手机动作 | 零阶保持 | 上一个控制指令会持续生效 |
| 视频帧 | 最近帧匹配 | 选择时间上最接近的画面 |

### 自测问题

- 为什么三路数据不一定同频？
- 为什么手机动作不用线性插值？

## 阶段 5：理解 FK 状态增强

重点文件：

```text
forward_kinematics.py
dh_params.example.json
```

原始机械臂通常只返回关节角：

```text
[j1, j2, j3, ...]
```

但你的任务关心末端执行器位置，所以需要 FK 算出：

```text
[x, y, z, yaw, pitch, roll]
```

最终 state：

```text
observation.state = [关节角] + [末端位姿]
```

### 自测问题

- 关节角和末端位姿有什么区别？
- DH 参数为什么必须是真实机械臂参数？

## 阶段 7：理解 ACT 模型在干什么

重点文件：

```text
src/lerobot/policies/act/modeling_act.py
```

ACT 的核心思想：

```text
当前观察 -> 预测未来一段动作
```

不是只预测下一步，而是预测一个 action chunk：

```text
action[t], action[t+1], action[t+2], ...
```

输入：

```text
observation.state
observation.images.cam
```

输出：

```text
action chunk
```

### 自测问题

- 为什么输出一段动作，而不是只输出一个动作？
- 摄像头画面对模型有什么帮助？

## 阶段 9：理解 loss

模型预测：

```text

```

```text

```


当前 ACT 主要用 L1 loss：


## 阶段 10：理解 A/B 学习质量对比

重点文件：

```text
offline_compare.py
```

它比较的是：

```text
A 模型在测试集上的动作误差
B 模型在测试集上的动作误差
```

判断逻辑：

| 结果 | 解释 |
|---|---|
| A 的误差更低 | 手机端显示采集的数据训练出的模型更接近人类动作 |
| B 的误差更低 | 电脑端显示采集的数据训练出的模型更接近人类动作 |
| 差异不显著 | 当前数据不足以证明哪组更好 |

### 自测问题

- held-out 测试集为什么不能参与训练？
- 为什么 A/B 独立采集时不要用 paired t-test？
